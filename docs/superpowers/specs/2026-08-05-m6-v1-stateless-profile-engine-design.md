# M6 v1.0 无状态画像引擎设计

## 1. 目标

重写 Python M6 画像引擎，使其成为符合 `profile-engine-contract.yaml` v1.0 的异步无状态计算服务。
引擎只消费 Java 传入的标准学习事件，在单次请求内完成知识掌握度、薄弱知识点、困惑点、近期关注点、
学习节奏、明确偏好、综合学习情况和画像摘要计算。

本次实现不读取任何模块物理表，不持久化画像，不修改 Java 调度器和画像写入器。

## 2. 已确认边界

### 2.1 当前数据来源

| 模块 | 使用的事件 | 画像用途 |
| --- | --- | --- |
| M1 | `answer_question`、`finish_practice` | 掌握度、学习节奏、做题表现 |
| M2 | `request_explanation`、`explanation_feedback` | 困惑与理解反馈、提问理解情况 |
| M3 | `weak_point_changed` | 薄弱状态、薄弱变化趋势、综合学习情况 |
| M4 | `lecture_interact` | 近期关注、课程交互描述 |
| M6 | `mark_reviewed`、`preference_changed` | 复习表现、学习节奏、明确偏好、讲解风格 |
| M7 | `ask_doubt` | 本地 NLP 困惑识别、追问情况 |

M5 与本次画像任务无关。合法的 M5 事件只记录服务端日志，不计入有效证据，也不改变画像结果。
Python 先完整支持 M3 事件；M3 尚未接通发布时，不阻塞其他模块的画像计算。

### 2.2 明确排除

- 不读取 `user_answers`、`wrong_question_book`、`conversation_messages`、`user_weak_points` 等物理表。
- 不连接数据库，不维护 Python 侧用户状态。
- 不使用 KMeans，不输出 visual、auditory、reading、kinesthetic 固定学习类型。
- 不根据 M4 播放行为猜测内容偏好。
- 不使用 M1 掌握得分或重复答错计算薄弱分，`WEAK` 只由 M3 薄弱事件判定。
- 不把原始提问文本、用户身份或完整事件发送给大模型。
- 不新增 v1.0 契约之外的 `warnings`、综合分等响应字段。

## 3. 文件职责

### 3.1 `src/landppt/m6/profile_engine.py`

完全重写为无状态领域计算模块，公开异步入口 `buildProfile()`。模块负责：

1. 在完整事件窗口中筛选有效证据。
2. 按知识点聚合答题和复习结果。
3. 分别计算 M1 掌握得分和 M3 薄弱状态，并解决新旧证据冲突。
4. 使用 M7 短文本规则和 M2 反馈计算困惑点。
5. 计算近期关注点、学习节奏和明确偏好。
6. 计算综合学习情况及画像置信度。
7. 调用 OpenAI 兼容接口生成摘要，失败时使用本地模板。
8. 构造严格的 v1.0 响应。

该文件不导入 M6 数据库连接、排期器或旧表适配器。

### 3.2 `src/landppt/m6/schemas.py`

保留两个现有 GET 查询接口需要的展示模型，重写画像相关 Pydantic 模型：

- 请求禁止未知顶层字段。
- 校验契约版本、UUID、正整数标识、版本、水位、事件顺序和时区时间。
- 校验事件类型与来源模块的一致性。
- 对当前使用的 M1、M2、M3、M4、M6、M7 事件执行字段级校验。
- 使用可辨识联合严格区分 `READY`、`INSUFFICIENT_DATA` 和 `NO_CHANGE`。

### 3.3 `src/landppt/m6/router.py`

- 删除 `POST /api/review/calculate-all`。
- 删除 `POST /api/events/process`。
- 将 `POST /api/internal/ai/build-profile` 改为正式 v1.0 异步入口。
- 保留知识状态和时间线两个 GET 接口，避免扩大本次画像引擎任务范围。
- 契约校验失败返回 HTTP 400；非大模型降级类的引擎不可用返回 HTTP 503。

Java 端后续停止两个旧定时调用，统一向正式画像接口发送完整 v1.0 请求。

## 4. 请求窗口和确定性

- 每次请求由 Java 提供最近 90 天、最多 1000 条足以独立重算画像的完整事件窗口。
- `events` 必须按 `dbEventId` 严格递增，不允许重复。
- Python 不使用上一版画像内容，`baseProfileVersion` 只用于计算目标版本。
- `FULL` 和 `INCREMENTAL` 都根据请求内完整窗口重算；调用方负责保证窗口完整。
- 计算函数接收可注入时钟，测试使用固定时间，生产使用 UTC 当前时间。
- 超过 90 天的事件不参与特征计算；超过 1000 条的请求视为参数错误。

## 5. 响应状态

| 条件 | 状态 | 目标版本 | `profile` | `knowledgeMastery` |
| --- | --- | --- | --- | --- |
| 无当前范围内的可用事件 | `NO_CHANGE` | 等于基础版本 | 不返回 | 不返回 |
| 1 至 4 条可用事件 | `INSUFFICIENT_DATA` | 基础版本加 1 | 不返回 | 空列表 |
| 至少 5 条可用事件 | `READY` | 基础版本加 1 | 返回 | 允许返回 |

`READY` 只表示画像达到最低发布门槛，不表示所有可选字段都有证据。无证据字段保持 `null` 或空列表。
`grade` 始终为 `null`，因为当前事件不包含年级事实。

## 6. 算法版本

初始算法版本为：

```text
m6-profile-v1.0.0
```

版本同时写入响应顶层和每条知识掌握结果。以下变化至少升级次版本：

- 权重或阈值变化；
- 时间衰减规则变化；
- 事件到特征的映射变化；
- 大模型提示词或本地摘要模板发生实质变化。

服务端日志记录 `requestId`、算法版本、摘要生成方式、模型名称和提示词版本，不记录密钥和原始学习文本。

## 7. M1 知识掌握度与 M3 薄弱知识点

### 7.1 掌握得分

```text
掌握得分 =
  正确率 × 55%
  + 难度加权正确率 × 15%
  + 独立完成度 × 15%
  + 近期正确率 × 15%
```

- 正确率使用 M1 答题及可映射为正确或错误的 M6 复习结果。
- 难度加权正确率只使用带 `difficulty` 的 M1 答题。
- 独立完成度根据正确结果和 `hintCount` 计算，提示越多得分越低。
- 近期正确率使用 30 天半衰期，越新的证据权重越高。
- 各分量缺失时按已有分量重新归一化，不把缺失项按 0 分处理。
- 最终得分限制在 0 至 1，并保留四位小数。

### 7.2 M3 薄弱分

薄弱分只使用同一知识点最新一条 M3 `weak_point_changed`：

```text
当前薄弱分 = latest(newScore)
```

- 本算法约定 M3 分数越高表示越薄弱，`newScore` 大于或等于 0.6 时判定为 `WEAK`。
- 如果 M3 内部使用相反分数方向，M3 发布事件前必须转换为本契约约定的薄弱分。
- `newScore` 小于 0.6 时，M3 不覆盖 M1 掌握状态。
- M1 答错仍然影响正确率和掌握得分，但不再生成薄弱分。
- M3 历史事件不取平均；旧事件只用于追溯变化，最新事件表达当前薄弱状态。
- 只有 M3、没有 M1 直接表现时，`masteryScore` 使用 `1 - newScore`，但非 `WEAK` 状态仍为
  `INSUFFICIENT_EVIDENCE`，不能仅凭“当前不薄弱”推断已经掌握。

### 7.3 状态

- 没有 M3 且 M1/M6 直接表现证据少于 5 条：`INSUFFICIENT_EVIDENCE`。
- M3 最新薄弱分大于或等于 0.6：候选状态为 `WEAK`。
- 答题数大于 10、原始正确率大于 0.8、掌握得分大于或等于 0.8：`MASTERED`。
- 未判定为 `MASTERED` 或 `WEAK`，且掌握得分大于或等于 0.6：`BASIC_MASTERY`。
- 其余具备至少 5 条直接表现证据的知识点：`CONSOLIDATING`。
- 没有 M3 时，即使 M1 掌握得分低于 0.4，也返回 `CONSOLIDATING`，不使用 M1 产生 `WEAK`。
- 不满足掌握硬门槛时，即使综合得分较高，也最多为 `BASIC_MASTERY`。

当 M1 候选状态为 `MASTERED`、M3 候选状态为 `WEAK` 时，比较两类证据的最后发生时间：

- 最新 M3 事件较新：最终为 `WEAK`；
- 最新 M1/M6 直接表现较新：最终为 `MASTERED`；
- 时间相同：使用更保守的 `WEAK`，并降低信号一致性。

### 7.4 趋势

- M1/M6 至少 6 条直接表现证据时，比较窗口前半段与后半段得分。
- M1/M6 差值大于 0.1 为 `IMPROVING`，小于 -0.1 为 `DECLINING`，否则为 `STABLE`。
- M3 使用最新事件的 `oldScore/newScore`：分数下降为 `IMPROVING`，分数上升为 `DECLINING`，
  相等为 `STABLE`。
- 两类趋势同时存在时，使用最后发生时间较新的趋势；时间相同且冲突时返回 `STABLE` 并降低一致性。

## 8. 困惑点 NLP

困惑点不使用 M3 或普通答错事件，只使用 M7 短文本和 M2 理解反馈。

### 8.1 本地规则

对 `ask_doubt.topic` 做 Unicode 归一化、大小写归一化和空白折叠，然后匹配：

| 模式示例 | 标准化困惑类型 |
| --- | --- |
| 为什么、为何、怎么会、`why` | 原因不理解 |
| 不懂、没懂、不明白、`don't understand` | 概念不理解 |
| 什么意思、含义、`what does ... mean` | 术语不理解 |
| 怎么做、如何计算、步骤 | 方法或步骤不理解 |
| 区别、差别、不同在哪里 | 概念混淆 |

`confusionTag` 是结构化强证据，`isFollowUp=true` 增加重复困惑证据。M2 中：

- `still_confused` 增加强困惑证据；
- `partly_understood` 表示部分缓解；
- `understood` 抵消未解决困惑。

### 8.2 隐私和契约限制

- 原始 `topic` 只在内存中分析，不发送给大模型，不写入日志。
- `recentConfusions.detail` 只保存标准化类型，不保存原文。
- 只有带 `kpId` 的困惑才能进入 `recentConfusions`，最多返回 5 条。
- 无 `kpId` 的提问只参与总体提问理解得分和摘要的匿名统计。
- 困惑证据使用 30 天半衰期。

## 9. 近期关注点

- 只统计带 `kpId` 的当前范围事件。
- 使用事件出现频率和 30 天时间衰减。
- 归一化为 0 至 1 权重，按权重降序，最多返回 5 条。
- 权重相同时，最后发生时间较新的知识点优先。

## 10. 学习节奏和明确偏好

### 10.1 学习节奏

最新的 M6 `preference_changed(learning_pace)` 优先。没有明确设置时：

- 使用 M1 `timeSpentSec` 和 M6 `mark_reviewed.timeSpentSec` 的中位数；
- 少于 5 条有效时长时返回 `null`；
- 小于 30 秒为 `fast`；
- 30 至 90 秒为 `moderate`；
- 大于 90 秒为 `slow`。

### 10.2 内容偏好和讲解风格

- 内容偏好只采信最新的 M6 `preference_changed(content_mode)`。
- 讲解风格只采信最新的 M6 `preference_changed(explanation_style)`。
- 未明确设置时分别返回空列表和 `null`。
- 行为数据不用于猜测固定偏好或讲解风格。

## 11. 综合学习情况

根据 2026-08 教师问卷结果（5 位教师，4 位 9 年以上经验），来源权重更新为：

```text
做题表现 24%
错题本 33.2%
提问理解 16.8%
薄弱点情况 26%
```

错题本没有独立输入，不能按 0 分处罚。M3 事件可用时，当前来源权重重新归一化为：

```text
做题表现 35.93%
提问理解 25.15%
薄弱点情况 38.92%
```

M3 尚未传入有效事件时，再对做题和提问来源重新归一化为 `58.82%/41.18%`，不阻塞画像生成。

- 做题表现来自 M1 答题、练习和 M6 复习结果。
- 提问理解来自 M2 理解反馈与 M7 追问、困惑模式。
- 薄弱点情况使用每个知识点最新 M3 `newScore` 的反向值 `1 - newScore`，按知识点取平均。
- 主动提问本身不扣分；未解决和反复困惑才降低得分。
- 只有一个来源有证据时，不生成整体学习情况结论。
- 综合分仅作为摘要生成的内部输入，不新增 v1.0 响应字段。

提问理解得分采用固定映射：

- M2 `understood` 记 1，`partly_understood` 记 0.5，`still_confused` 记 0；
- M7 首次主动提问只用于识别困惑，不直接计入好坏评分；
- M7 `isFollowUp=true` 记为未解决证据 0；
- 没有 M2 理解反馈且没有 M7 追问时，提问来源视为证据不足，不以 0 分处罚。

做题表现优先使用按知识点计算的掌握得分。`finish_practice` 只在同一 `sessionId` 没有逐题
`answer_question` 时补充总体正确率，避免同一练习被重复计算。

内部解释区间：

| 得分 | 描述 |
| --- | --- |
| 0.80 至 1.00 | 整体表现良好 |
| 0.60 至 0.80 | 学习状态基本稳定 |
| 0.40 至 0.60 | 存在需要加强的部分 |
| 0.00 至 0.40 | 需要优先关注 |

教师问卷有效样本充足后，更新来源权重、测试和设计依据，并将算法版本升级到 `m6-profile-v1.1.0` 或更高。

## 12. 画像置信度

```text
整体置信度 =
  有效事件数量充足度 × 50%
  + 加权来源覆盖度 × 30%
  + 同类信号一致性 × 20%
```

- 20 条有效事件时，数量充足度达到上限。
- 来源覆盖度按当前实际支持的做题、提问与 M3 薄弱点来源计算。
- 同类信号冲突时降低一致性。
- 最高限制为 0.95，保留三位小数。

## 13. 大模型摘要

### 13.1 调用

- 使用项目已有 OpenAI Python SDK 的异步客户端。
- 复用 `OPENAI_API_KEY`、`OPENAI_BASE_URL`、`OPENAI_MODEL`。
- 默认超时 10 秒，可由 `PROFILE_LLM_TIMEOUT_SECONDS` 调整。
- 不自动重试。
- 测试注入假客户端，不访问真实网络。

提示词版本固定为 `m6-summary-prompt-v1`，与算法版本一起写入服务端日志。

### 13.2 输入与输出

只发送脱敏结构化结果：掌握状态、标准化困惑类型、近期关注、学习节奏、明确偏好、综合学习情况和置信度。
摘要使用中文，目标 150 至 300 字，包含总体情况、掌握与薄弱点、困惑、偏好和一条建议。

提示词禁止新增知识点名称、身份、年级或未计算事实。空响应使用本地模板，超长响应在完整 Unicode 字符边界截断至 300 字。

### 13.3 降级

以下情况返回本地模板，不影响 `READY`：

- 未配置 API Key、模型或地址；
- 超时、限流或 API 异常；
- 空响应或无法提取文本。

降级只记录服务端 `WARN` 日志，不添加契约外字段，不把警告写入面向学生或教师的摘要。

## 14. 错误处理和安全

- 顶层请求、版本、水位、顺序、事件字段或来源不合法：HTTP 400，中文错误信息。
- 缺少服务认证由现有认证层返回 401 或 403。
- 非大模型降级类的引擎不可用：HTTP 503。
- 不记录 API Key、Bearer 凭据、原始提问、完整事件或用户隐私。
- 日志包含时间、模块、级别、`requestId`、算法版本和无敏感信息的失败类别。

## 15. 测试与验收

采用 TDD，新增 M6 专用 pytest 测试，覆盖：

1. v1.0 请求、事件和三种响应的严格序列化。
2. 事件水位、严格递增顺序、90 天和 1000 条窗口限制。
3. 5 条证据、10 次答题、80% 正确率等边界。
4. M1 掌握度、M3 薄弱分、时间优先冲突规则和趋势。
5. 中英文困惑模式、M2 反馈抵消、原文不泄漏。
6. M3 参与薄弱状态但不参与困惑点；M5 不参与画像。
7. 近期关注、学习节奏和最新明确偏好。
8. M3 有无事件时的 `53.33%/26.67%/20.00%` 与 `66.67%/33.33%` 权重切换。
9. 算法版本在顶层和知识掌握结果中一致。
10. 大模型成功、未配置、超时、异常、空响应和超长响应。
11. 正式 POST 路由可用，两个旧 POST 路由删除，两个 GET 路由保留。
12. 现有 `tests/user_profile` 回归测试继续通过。

新增 M6 核心代码的语句覆盖率目标不低于 80%。测试不得访问真实大模型或数据库。
