## 四、事件格式规范

### 4.1 通用字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `eventType` | string | 是 | `"weak_point_changed"` |
| `sourceModule` | string | 是 | **必须填 `"M3"`**，不能填其他值 |
| `userId` | string | 是 | 学生用户 ID |
| `kpId` | string | **强烈建议** | 知识点 ID，关联到具体知识点。事件中强烈建议携带此字段，否则引擎无法将薄弱点变化关联到具体知识点 |
| `occurredAt` | string (ISO 8601) | 是 | 事件发生时间，**必须包含时区信息**，例如 `2026-08-05T12:00:00+08:00` |

### 4.2 `weak_point_changed` 专属字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `oldScore` | float | 是 | 变化前的薄弱度分数，范围 0-1（0 表示完全掌握，1 表示极度薄弱） |
| `newScore` | float | 是 | 变化后的薄弱度分数，范围 0-1 |
| `reason` | enum(string) | 是 | 薄弱点变化原因，**必须为以下枚举值之一**：<br>`ACCURACY_DROP` -- 正确率持续下降<br>`REPEATED_ERROR` -- 同知识点反复出错<br>`TEACHER_MARKED` -- 教师手动标记<br>`RECALCULATED` -- 薄弱度引擎重新计算 |

## 五、特别注意事项

### 5.1 M3 是唯一能触发 WEAK 状态的模块

画像引擎中知识点掌握状态分为三级：

| 状态 | 含义 | 触发条件 |
|---|---|---|
| `MASTERED` | 已掌握 | M1 持续高分 |
| `CONSOLIDATING` | 巩固中 | M1 低分（M1 最多到此处） |
| `WEAK` | 薄弱 | **仅 M3 的 `weak_point_changed` 事件可触发** |

**M1 学生的答题低分只会将知识点标记为 `CONSOLIDATING`，不会标记为 `WEAK`。只有 M3 组通过薄弱度算法判定学生存在薄弱点时，才会将知识点标记为 `WEAK`。** 这一定位决定了 M3 事件数据的不可替代性。

### 5.2 `newScore >= 0.6` 触发 WEAK 标记

当 `weak_point_changed` 事件中的 `newScore`（变化后的薄弱度分数）大于等于 0.6 时，引擎将对该学生的该知识点触发 `WEAK` 标记。

```json
{
  "oldScore": 0.45,
  "newScore": 0.72,   // >= 0.6，将触发 WEAK 标记
  "reason": "ACCURACY_DROP"
}
```

### 5.3 冲突处理规则："较新的证据优先"

当同一知识点出现多条 `weak_point_changed` 事件时，引擎采用 **"较新的证据优先"** 策略：

- 按 `occurredAt` 时间排序，最新事件的状态覆盖旧事件
- 这意味着如果一条新事件将 `newScore` 降至 0.6 以下，WEAK 状态会被解除
- **此规则经用户确认，请确保 `occurredAt` 时间戳准确**

### 5.4 M3-Only 知识点（无 M1 答题记录）

对于只有 M3 薄弱点数据而无 M1 答题记录的知识点，引擎采用以下公式计算掌握度得分：

```
掌握度得分 = 1 - latest(newScore)
```

即用最新一条 `weak_point_changed` 事件的 `newScore` 反推掌握度。这意味着：
- `newScore = 0.3` --> 掌握度 = 0.7（较好）
- `newScore = 0.8` --> 掌握度 = 0.2（薄弱）

### 5.5 `occurredAt` 时区要求

```json
// 正确
"occurredAt": "2026-08-05T12:00:00+08:00"

// 错误 -- 缺少时区
"occurredAt": "2026-08-05T12:00:00"
```
