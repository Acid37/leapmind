## 二、网关层核心任务

### 2.1 网关层数据流

新架构下网关层的数据流如下：

```
各模块 → Java 事件采集服务 (POST /api/events/collect)
       → event_collections 表（processed=0）
       → 网关层读取未处理事件
       → 转换为 v1.0 格式
       → 调用 Python 引擎 (POST /api/internal/ai/build-profile)
       → 标记 processed=1 (PUT /api/events/{eventId}/processed)
```

你需要实现的核心逻辑：
1. **读取**：从 `event_collections` 表读取 `processed=0` 的事件
2. **转换**：将事件转换为 v1.0 契约格式（补充 `dbEventId`、`eventId`、`sourceModule`、`schemaVersion`、`sessionId`、`kpId`、`traceId` 等公共字段）
3. **调用**：调用 Python 引擎的 `POST /api/internal/ai/build-profile`
4. **标记**：调用成功后标记 `processed=1`

### 2.2 调度策略

建议定时调度频率：
- **活跃用户**：每 5-10 分钟执行一次增量更新（`mode: "INCREMENTAL"`）
- **非活跃用户**：每 1 小时执行一次检查，无新事件则跳过
- **全量重建**：每天凌晨执行一次（`mode: "FULL"`），作为兜底校准
