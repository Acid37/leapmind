# M6 v1.0 画像引擎事件接入通知（M7 组）

**致：周贺浚（组长）及 M7 实时打断提问组全体**

---

## 一、事件类型

M7 组需要向 M6 画像引擎提交以下事件：

| 项目 | 内容 |
|------|------|
| 事件类型 | `ask_doubt`（提问） |
| sourceModule | `"M7"`（必填，固定值） |
| 用途 | 记录学生实时提问行为，用于困惑度分析 |

---

## 二、事件字段定义

### 2.1 必填字段

| 字段名 | 类型 | 说明 | 格式约束 |
|--------|------|------|----------|
| `topic` | string | 提问主题原文 | 1-120 个 Unicode 码点 |
| `confusionTag` | enum | 困惑类型标签 | `concept_unclear` / `formula_confusion` / `step_unclear` / `application_difficulty` / `careless_error` |
| `isFollowUp` | bool | 是否为追问 | 严格 JSON 布尔值（`true` 或 `false`） |
| `occurredAt` | string | 事件发生时间 | ISO 8601 带时区，如 `2026-08-05T12:00:00+08:00` |

### 2.2 可选字段（通用）

| 字段名 | 类型 | 说明 |
|--------|------|------|
| `sessionId` | string | 会话ID，为 null 时省略不传 |
| `kpId` | string | 知识点ID，为 null 时省略不传 |
| `traceId` | string | 链路追踪ID，为 null 时省略不传 |

---

## 三、事件 JSON 示例

```json
{
  "type": "ask_doubt",
  "sourceModule": "M7",
  "data": {
    "topic": "为什么牛顿第二定律中 F=ma 的 m 是惯性质量而不是引力质量？",
    "confusionTag": "concept_unclear",
    "isFollowUp": false
  },
  "occurredAt": "2026-08-05T14:30:00+08:00"
}
```

追问示例：

```json
{
  "type": "ask_doubt",
  "sourceModule": "M7",
  "data": {
    "topic": "那在非惯性系中这个公式还成立吗？",
    "confusionTag": "concept_unclear",
    "isFollowUp": true
  },
  "occurredAt": "2026-08-05T14:32:00+08:00"
}
```

## 四、隐私保护机制（重要！）

### 4.1 topic 原文处理流程

为保护用户隐私，`topic` 原始文本**不会出现在任何日志、摘要载荷和 API 响应中**。引擎内部处理流程如下：

```
topic 原文 → NFKC 标准化 → casefold（小写折叠） → 正则匹配 → 输出标准化标签 → 丢弃原文
```

### 4.2 五类困惑正则模式

引擎内置 5 种正则模式，对 topic 文本进行语义匹配，匹配到的类型**优先级高于 `confusionTag`**：

| 序号 | 正则模式 | 匹配的语义类型 |
|------|----------|----------------|
| 1 | 原因不理解 | 对某个现象或结论的原因/原理不理解 |
| 2 | 概念不理解 | 对某个术语或概念的定义不理解 |
| 3 | 术语不理解 | 对某个专业术语或符号不认识 |
| 4 | 方法或步骤不理解 | 对解题方法或推导步骤不理解 |
| 5 | 概念混淆 | 将两个相似概念混淆 |

正则匹配到的困惑类型会作为画像输出的主要依据，`confusionTag` 作为降级备选。

## 五、追问机制

### 5.1 isFollowUp 字段要求

- 必须是严格的 JSON 布尔值：`true` 或 `false`
- 不允许使用字符串 `"true"` / `"false"` 或数字 `1` / `0`

### 5.2 追问对画像的影响

| isFollowUp 值 | 对理解度的影响 |
|---------------|---------------|
| `true`（追问） | 当前事件计为**理解度 0**（表示学生没听懂，继续追问） |
| `false`（首次提问） | **不计入理解度**（单独一次提问无法判断理解程度） |

---

## 六、特别注意事项

- `topic` 长度 1-120 个 Unicode 码点，超长会被拒绝
- `confusionTag` 必须在 5 个枚举值中选择
- `occurredAt` 必须包含时区信息
- data 对象不允许包含上述字段之外的额外字段
- 可选字段值为 null 时直接省略，禁止显式传 `null`

---

## 七、常见错误预防

| 错误场景 | 错误做法 | 正确做法 |
|----------|----------|----------|
| isFollowUp 类型错误 | `"isFollowUp": "true"`（字符串） | `"isFollowUp": true`（布尔值） |
| isFollowUp 数字错误 | `"isFollowUp": 1` | `"isFollowUp": true` |
| null 字段显式传递 | `"traceId": null` | 直接省略该字段 |
| 额外字段 | data 中包含 `answer` 等未定义字段 | data 对象仅包含上述定义字段 |
| topic 为空 | `"topic": ""` | topic 必须 1-120 个 Unicode 码点 |
| topic 超长 | 超过 120 个 Unicode 码点的文本 | 截断或让前端限制输入长度 |
| confusionTag 拼写 | `"confusionTag": "concept_unclear"`（少了下划线） | 严格使用枚举值之一 |
| 时区缺失 | `"occurredAt": "2026-08-05T12:00:00Z"`（Z 时区可接受） | 推荐使用 `+08:00` 格式，`Z` 也可接受 |
