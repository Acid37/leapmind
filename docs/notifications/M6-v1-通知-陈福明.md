## 一、变更概述

M6 v1.0 无状态画像引擎已完成重写（221测试/98.2%覆盖率），你的负责模块需要评估与新架构的兼容性。

## 二、关键架构变更：无状态引擎

v1.0 画像引擎的核心变化是**从有状态到无状态**：

| 维度 | 旧架构 | 新架构（v1.0） |
|---|---|---|
| 数据读取 | 直读数据库（event_collections 表） | 不直读数据库，由网关传入事件数组 |
| 画像持久化 | 计算结果写入数据库 | 不持久化画像，每次调用返回计算结果 |
| 状态管理 | 依赖数据库中的上次画像版本 | 完全无状态，通过 `baseProfileVersion` 参数传递 |

### 对遗忘曲线模块的影响评估

你负责的**艾宾浩斯遗忘曲线**（基于 `review_schedules` 表）需要评估：

1. **`review_schedules` 表计算逻辑保持不变**：该表的增删改查仍通过 `GET /api/user-profile/{userId}/knowledge-status` 查询，不经过画像引擎
2. **复习计划提醒**：吴敏希负责的复习提醒 API 不受本次变更影响，遗忘曲线的底层逻辑无需调整
3. **需要确认**：`review_schedules` 表中的数据是否依赖旧的画像计算结果？如果是，需要改为通过新引擎的 `knowledgeMastery.masteryScore` 来初始化

### 对增量更新逻辑的影响评估

你负责的**画像增量更新**需要适配新架构：

1. **`INCREMENTAL` 模式**：新引擎支持 `mode: "INCREMENTAL"`，通过 `baseProfileVersion` + `fromEventIdExclusive` 实现增量
2. **增量触发时机**：需要定义何时触发增量更新（关注吴敏希的网关调度逻辑）
3. **需要确认**：你现有的增量更新逻辑（如果有独立代码）是否需要重写为调用引擎的 `INCREMENTAL` 模式

## 三、困惑点 NLP 现状

v1.0 引擎已实现**本地正则困惑检测**，支持 5 种困惑类型：

- 概念混淆（`concept_confusion`）
- 公式误用（`formula_misuse`）
- 步骤遗漏（`step_omission`）
- 因果颠倒（`causal_reversal`）
- 符号理解错误（`symbol_misunderstanding`）

重要约束：**原始 topic 文本不进入任何输出**，困惑检测基于本地规则，不依赖外部 NLP 服务。你协助困惑点 NLP 的角色目前侧重于验证检测准确率和补充边界 case。
