# M6 v1.0 画像引擎 -- M2 组事件接入通知

**致：阳睿（接口人）、王圳、孔维诚 及 M2 组全体**

---

## 一、背景

M6 v1.0 无状态画像引擎已开发完成。引擎从各模块的 Java 事件采集服务获取事件数据，进行用户画像计算（掌握度趋势、薄弱点识别、困惑分析、近期关注等）。

M2 组的拍照答疑与 AI 讲题功能产生的事件是画像引擎"困惑分析"和"近期关注"两个维度的核心数据来源。

请 M2 组各位按照以下规范提交事件数据。

---

## 二、需要提交的事件类型

M2 组需要提交以下 **2 种** 事件：

| 事件类型 | 说明 | 负责人 |
|---|---|---|
| `request_explanation` | 学生请求 AI 讲解（每次发起讲题即上报） | 阳睿、王圳 |
| `explanation_feedback` | 学生对讲解的反馈（听完讲解后的理解程度） | 阳睿、王圳 |

---

## 三、事件格式规范

### 3.1 通用字段（两个事件都需包含）

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `eventType` | string | 是 | `"request_explanation"` 或 `"explanation_feedback"` |
| `sourceModule` | string | 是 | **必须填 `"M2"`**，不能填其他值 |
| `userId` | string | 是 | 学生用户 ID |
| `explainId` | string | 是 | 讲解会话 ID，格式严格：`[A-Za-z0-9][A-Za-z0-9._:-]{0,63}`，即**必须以字母或数字开头**，后续可包含字母、数字、`.`、`_`、`:`、`-`，总长度 1-64 |
| `occurredAt` | string (ISO 8601) | 是 | 事件发生时间，**必须包含时区信息**，例如 `2026-08-05T12:00:00+08:00` |

### 3.2 `request_explanation` 专属字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `explainId` | string | 是 | 讲解会话 ID，需符合上述格式规范 |
| `reasonTag` | enum(string) | 是 | 请求讲解的原因，**必须为以下枚举值之一**：<br>`WRONG_ANSWER` -- 答错后请求讲解<br>`REPEATED_ERROR` -- 同一知识点反复出错<br>`USER_REQUEST` -- 学生主动请求讲解<br>`LOW_CONFIDENCE` -- 答题信心不足<br>`REVIEW_NEEDED` -- 复习需要 |

### 3.3 `explanation_feedback` 专属字段

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `explainId` | string | 是 | 讲解会话 ID，与 `request_explanation` 中的 explainId 对应 |
| `feedback` | enum(string) | 是 | 学生反馈的理解程度，**必须为以下枚举值之一**：<br>`understood` -- 完全理解<br>`partly_understood` -- 部分理解<br>`still_confused` -- 仍然困惑 |
| `repeatCount` | int | 是 | 同一讲解的重复播放/查看次数，范围 0-100 |

## 四、特别注意事项

### 4.1 `explainId` 格式规范

```
explainId 正则: ^[A-Za-z0-9][A-Za-z0-9._:-]{0,63}$
```

- 必须以字母或数字开头
- 后续可包含字母、数字、`.`、`_`、`:`、`-`
- 总长度 1-64 字符
- `request_explanation` 和 `explanation_feedback` 必须使用**相同的 explainId** 关联同一讲解会话

```json
// 正确
"explainId": "exp_20260805_001"
"explainId": "EXP-20260805-001"
"explainId": "a1b2c3"

// 错误
"explainId": "_exp_001"           // 不能以下划线开头
"explainId": "-exp-001"           // 不能以连字符开头
"explainId": "exp@001"            // 包含非法字符 @
```

### 4.2 反馈事件的 `kpId` 继承规则

`explanation_feedback` 事件中，知识点 ID 的确定规则为：

1. **优先使用反馈事件自身的 `kpId`**（如果携带）
2. 若未携带，则从 **同一 `explainId` 下最近一条 `request_explanation` 事件**继承 `kpId`

建议在 `explanation_feedback` 中显式携带 `kpId`，避免因继承链路中断导致数据丢失。

### 4.3 困惑权重映射

引擎根据学生对讲解的反馈计算困惑权重，映射关系如下：

| feedback 值 | 困惑权重 | 含义 |
|---|---|---|
| `understood` | -2.0 | 完全理解，困惑大幅降低 |
| `partly_understood` | 0.5 | 部分理解，仍有轻微困惑 |
| `still_confused` | 2.0 | 仍然困惑，困惑显著增加 |

此权重直接参与困惑 NLP 分析和近期关注计算，影响用户的画像标签。

### 4.4 `occurredAt` 时区要求

```json
// 正确
"occurredAt": "2026-08-05T12:00:00+08:00"

// 错误 -- 缺少时区
"occurredAt": "2026-08-05T12:00:00"
```

## 五、事件 JSON 示例

### `request_explanation` 示例

```json
{
  "eventType": "request_explanation",
  "sourceModule": "M2",
  "userId": "student_001",
  "explainId": "exp_20260805_001",
  "kpId": "kp_quadratic_equation_001",
  "occurredAt": "2026-08-05T12:05:00+08:00",
  "eventData": {
    "reasonTag": "WRONG_ANSWER"
  }
}
```

### `explanation_feedback` 示例

```json
{
  "eventType": "explanation_feedback",
  "sourceModule": "M2",
  "userId": "student_001",
  "explainId": "exp_20260805_001",
  "kpId": "kp_quadratic_equation_001",
  "occurredAt": "2026-08-05T12:10:00+08:00",
  "eventData": {
    "feedback": "partly_understood",
    "repeatCount": 2
  }
}
```

## 六、常见错误预防清单

- [ ] `sourceModule` 确认填写 `"M2"`
- [ ] `explainId` 确认以字母或数字开头，不含非法字符
- [ ] `request_explanation` 和 `explanation_feedback` 使用相同的 explainId 关联
- [ ] `reasonTag` 确认使用枚举值（全大写下划线格式）
- [ ] `feedback` 确认使用枚举值（全小写下划线格式）
- [ ] `occurredAt` 确认包含时区信息（`+08:00`）
- [ ] 反馈事件建议显式携带 `kpId`，避免继承失败
